═══════════════════════════════════════════════════════════
🚨 الجزء 1: الأخطاء الحقيقية التي وقعت (تعلّم منها)
═══════════════════════════════════════════════════════════

الخطأ 1: استخدام اسم غير مستورد
─────────────────────────────────
❌ ما حدث:
   deepseek كتب:
   oversized_data = {"data": "A" * (core_module._MAX_PAYLOAD_BYTES + 1)}

   لكن core_module غير مستورد في الملف.

   النتيجة: NameError: name 'core_module' is not defined

✅ الحل:
   - استورد ما تحتاجه بشكل صريح.
   - من channel.core import _MAX_PAYLOAD_BYTES
   - ثم استخدم _MAX_PAYLOAD_BYTES مباشرة.

📏 القاعدة:
   لا تفترض وجود أي اسم. تحقق أولًا.

─────────────────────────────────
الخطأ 2: عدم عرض الملف قبل التعديل
─────────────────────────────────
❌ ما حدث:
   deepseek اقترح اختبارات جديدة دون رؤية:
   - الـ imports الحالية في الملف.
   - أسماء الدوال الحرفية.
   - الرسائل الحرفية في الكود الأصلي.

✅ الحل:
   قبل أي إضافة إلى ملف، اطلب مني:
   - head -25 path/file.py (لرؤية imports)
   - tail -20 path/file.py (لرؤية النهاية)
   - sed -n 'N,Mp' path/file.py (لرؤية الجزء المراد تعديله)

📏 القاعدة:
   لا تخمّن. اعرض أولًا.

─────────────────────────────────
الخطأ 3: اختبارات خارج الفئة (Class)
─────────────────────────────────
❌ ما حدث:
   deepseek كتب:
   def test_canonicalize_rejects_non_serializable_payload():
       ...

   في نهاية الملف، خارج أي class.

   النتيجة: يخالف نمطنا، ويسبب مشاكل تنظيمية.

✅ الحل:
   كل اختبار جديد في فئة:
   class TestCanonicalize:
       """Test _canonicalize."""

       def test_rejects_non_serializable(self) -> None:
           ...

📏 القاعدة:
   لا اختبار خارج فئة. أبدًا.

─────────────────────────────────
الخطأ 4: افتراض نص رسالة الخطأ
─────────────────────────────────
❌ ما حدث:
   deepseek كتب:
   with pytest.raises(ValueError, match="payload not serializable"):

   لكنه لم يتحقق من الرسالة الحرفية في الكود الأصلي.

✅ الحل:
   قبل كتابة match=، اعرض الكود الأصلي:
   sed -n '240,250p' src/channel/core.py

   ثم اقرأ الرسالة الحرفية.

📏 القاعدة:
   الرسائل حساسة. لا تخمّنها.

─────────────────────────────────
الخطأ 5: إضافة imports في نهاية الملف
─────────────────────────────────
❌ ما حدث (محتمل):
   deepseek قد يضيف:
   from channel.core import _MAX_PAYLOAD_BYTES

   في نهاية الملف.

   النتيجة: ruff سيرفض (ترتيب الاستيرادات).

✅ الحل:
   الـ imports تُضاف في الأعلى فقط.
   إذا لزم، استخدم script Python لتعديل المكان الصحيح:

   python3 -c "
   p = 'path/file.py'
   s = open(p).read()
   old = 'from channel.core import ('
   new = 'from channel.core import (\n    _MAX_PAYLOAD_BYTES,'
   s = s.replace(old, new, 1)
   open(p, 'w').write(s)
   "

📏 القاعدة:
   imports في الأعلى. لا استثناء.

═══════════════════════════════════════════════════════════
📏 الجزء 2: القواعد العشر الصارمة
═══════════════════════════════════════════════════════════

القاعدة 1: لا تخمين
─────────────
إذا لم ترَ الكود، لا تكتب عنه.
اطلب لقطة أولًا.

القاعدة 2: لا تفترض imports
─────────────
إذا استخدمت اسمًا، تأكد أنه مستورد.
استخدم head -25 لعرض الـ imports.

القاعدة 3: اقرأ الرسائل
─────────────
إذا كنت ستستخدم match="..."، اعرض الكود الأصلي أولًا.

القاعدة 4: كل اختبار في فئة
─────────────
class TestX:
    def test_y(self) -> None:
        ...

القاعدة 5: imports في الأعلى
─────────────
لا تُضف import في نهاية الملف.

القاعدة 6: خطوة واحدة، لقطة
─────────────
لا تعطني 3 أوامر دفعة واحدة.
أمر واحد. لقطة. ثم التالي.

القاعدة 7: لا sed، لا python lines[N:M]
─────────────
استخدم heredoc (cat > ... << 'ENDOFFILE') دائمًا.

القاعدة 8: تحقق بعد كل تعديل
─────────────
head -10 path/file.py
tail -10 path/file.py
wc -l path/file.py

القاعدة 9: عندما تخطئ، اعترف
─────────────
لا تحاول إخفاء الخطأ بمزيد من الأوامر.
قل: "أخطأت. لنُصلح."

القاعدة 10: لا مجاملة بلا محتوى
─────────────
"ممتاز!" بدون شرح = لا قيمة.
"هذا الأمر يعمل لأن..." = قيمة.

═══════════════════════════════════════════════════════════
📋 الجزء 3: قائمة ما قبل كتابة أي اختبار
═══════════════════════════════════════════════════════════

قبل كتابة اختبار جديد، يجب أن تتحقق من:

[ ] 1. عرض imports الملف: head -25 tests/unit/.../test_x.py
[ ] 2. عرض نهاية الملف: tail -20 tests/unit/.../test_x.py
[ ] 3. عرض الكود المستهدف: sed -n 'N,Mp' src/...
[ ] 4. قراءة الرسائل الحرفية في src.
[ ] 5. معرفة اسم الفئة المراد الاختبار لها.
[ ] 6. التأكد من وجود كل import مطلوب.
[ ] 7. كتابة الاختبار في فئة class TestX:.
[ ] 8. استخدام -> None على كل دالة اختبار.
[ ] 9. استخدام pytest.raises مع match= للرسائل الحرفية.
[ ] 10. تشغيل pytest -v بعد الإضافة.

🎯 الجزء 4: أمثلة (خطأ vs صحيح)
═══════════════════════════════════════════════════════════

مثال 1: import
─────────────
❌ خطأ:
   oversized_data = {"data": "A" * (core_module._MAX_PAYLOAD_BYTES + 1)}
   (بلا import)

✅ صحيح:
   # في أعلى الملف:
   from channel.core import _MAX_PAYLOAD_BYTES

   # في الاختبار:
   oversized_data = {"data": "A" * (_MAX_PAYLOAD_BYTES + 1)}

مثال 2: فئة
─────────────
❌ خطأ:
   def test_canonicalize_rejects_non_serializable_payload():
       with pytest.raises(ValueError, match="payload not serializable"):
           SecureAgentChannel._canonicalize({"key": {1, 2, 3}})

✅ صحيح:
   class TestCanonicalize:
       """Test _canonicalize JSON handling."""

       def test_rejects_non_serializable_payload(self) -> None:
           with pytest.raises(ValueError, match="payload not serializable"):
               SecureAgentChannel._canonicalize({"key": {1, 2, 3}})

مثال 3: التحقق قبل الافتراض
─────────────
❌ خطأ:
   اكتب الاختبار مباشرة.

✅ صحيح:
   الخطوة 1: أرسل لقطة لـ sed -n '240,250p' src/channel/core.py.
   الخطوة 2: انتظر لقطتي.
   الخطوة 3: بناءً على ما تراه، اكتب الاختبار.
   الخطوة 4: أضف الأمر (heredoc).
   الخطوة 5: شغّل pytest.

═══════════════════════════════════════════════════════════
🛠️ الجزء 5: الأدوات والأوامر المسموحة
═══════════════════════════════════════════════════════════

✅ مسموح:
─────────────
- cat > path << 'ENDOFFILE' ... ENDOFFILE
- cat >> path << 'ENDOFFILE' ... ENDOFFILE
- head -N path
- tail -N path
- wc -l path
- sed -n 'N,Mp' path
- grep "pattern" path
- ls path
- mkdir -p path
- touch path
- uv run pytest tests/.../test_x.py -v
- uv run pytest ... --cov=...

❌ ممنوع:
─────────────
- sed -i 's|...|...|' path
- python3 -c "lines[N:M] = ..."
- استبدال نص بلا heredoc
- أي أمر يعتمد على رقم سطر ثابت

🎓 الجزء 6: عند حدوث خطأ
═══════════════════════════════════════════════════════════

الخطوة 1: توقف
─────────────
لا تُكمل أي شيء.
لا تُصلح بلا فهم.

الخطوة 2: اطلب لقطة
─────────────
"أرسل لقطة للخطأ كاملًا."

الخطوة 3: حلّل
─────────────
- ما نوع الخطأ؟ (NameError, ValueError, ...)
- أين حدث؟
- لماذا؟

الخطوة 4: اقترح حلًا واحدًا
─────────────
لا تُعطني 3 حلول.
حل واحد، واضح.

الخطوة 5: نفّذ
─────────────
أمر واحد. ثم لقطة.
